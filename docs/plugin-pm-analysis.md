## 一、竞品分析

### 1.1 PingCode（现代化路线代表）

**产品架构**（相关子系统）：
- **Projects**：项目协作核心——需求 / 任务 / 缺陷 / 迭代 / 里程碑
- **Wiki**：知识库文档（与工作项双向关联）
- **Goals / Testhub / Insight / Pipeline**：目标、测试、效能度量、流水线（本项目暂不涉及）

**布局与交互**（关键借鉴点）：
1. **全局层**：顶栏 = 产品切换 + 搜索 + 通知 + 头像；**左侧固定两条导航**——
   - 第一条（窄 Rail）：工作台/项目列表入口
   - 第二条（项目内导航）：当前项目的模块菜单（需求 / 迭代 / 任务 / 缺陷 / 版本 / 文件 / 页面 / 设置），**带各模块数量徽标**
2. **项目内三层**：项目（空间）→ 工作项类型视图（需求列表/看板/甘特）→ 工作项详情（右侧抽屉，占屏 ~40%）
3. **视图体系**：每个类型模块内置 **看板 / 表格 / 甘特 / 日历** 多视图，视图可保存（分组方式 + 筛选条件 = 一个命名视图）
4. **看板**：按状态分列；卡片显示 类型图标+编号+标题+标签+负责人头像+优先级；**拖拽跨列=状态流转**；列可折叠
5. **工作项详情**：标题行内编辑；属性区（状态/负责人/迭代/优先级/里程碑，全部下拉点选即时保存）；描述富文本；**关联区**（子工作项/关联工作项/关联页面( Wiki 文档)/代码/PR）；**活动流**（全部变更历史时间线）；评论
6. **亮点机制**：
   - 工作项编号（如 `PROJ-12`）全局唯一可引用，`#12` 自动链接
   - 父子工作项（需求拆子任务，父进度=子项汇总）
   - 自动化规则（当状态变为 X → 指派给 Y…）
   - **与 Wiki 互链**：工作项详情可挂多篇 Wiki 页面；Wiki 里 `@工作项` 反向链接

### 1.2 禅道（全流程路线代表）

**核心理念——三层对象模型**：
```
产品（Product，管需求） → 项目/执行（Project/Execution，管任务）→ QA（管缺陷/用例）
需求 story ──拆解──> 任务 task ──发现──> 缺陷 bug
```

**流程闭环**（关键借鉴点）：
1. 产品经理维护**需求池**（来源/评审/变更纪律）
2. 立项/迭代规划：从需求池挑选 → **分解为任务**（工时估算/指派）
3. 开发完成任务、测试提**缺陷**、缺陷关联需求
4. **状态机严格**：需求（草稿/激活/已变更/关闭）、任务（未开始/进行/已完成/已暂停/已取消/已关闭）、缺陷（激活/已解决/已关闭），每次变更记录**操作历史**
5. **报表**：燃尽图、统计（需求变更率/缺陷分布/工作量）

**功能面**：待办（我的任务/我的缺陷/我的需求）、甘特、日历、文档库（与项目关联）、权限角色。

**短板（对我们是机会）**：界面重、上手成本高、文档能力弱（禅道文档简单，Wiki 需另购）——**BaseForge 的笔记/编辑器是天然强项**，应把「交付文档」做成一等公民而非附属。

## 二、BaseForge 场景定位（设计前提）

1. **底座是笔记/知识库**：交付文档（需求文档、方案、纪要）必须复用内置 tiptap 编辑器——工作项只是"把文档组织进流程"的骨架。这是对 PingCode（Wiki 另购）与禅道（文档弱）的**差异化优势**。
2. **单用户/小团队优先**：不做企业权限/多部门；workspaceId 字段预留。
3. **本地优先**：SQLite 存储、离线可用；git 平台同步为增强而非依赖。
4. **插件化**：PM = 官方内置插件（registry 管理，可停用），不侵入核心笔记功能。

## 五、完整改进计划（分四期）

### M1 布局与侧栏整合（回应「侧栏」问题）—— 目标：入口与导航对齐宿主习惯
改动清单：
1. `SidebarNext.tsx`：新增 `sidebarView === "projects"` 分支（sbx-view 风格）——
   项目列表（计数）→ 点击展开该项目工单（按状态分组：待处理/进行中/待验证/已完成）
   → 工单行点击=打开详情抽屉（复用 PmCenter 的 ItemDrawer 抽成共享组件）
   → 工单行快捷按钮：状态推进（→下个状态）、打开笔记
   → 顶部：新建项目/新建工作项/「在主区打开」
2. `NavRailNext.tsx`：pm 徽章点击 → `actions.setViewMode("projects")` + `nowen:sidebar-view`（侧栏同步切到 PM 面板）——**侧栏+主区同时就位**（与 tasks/diary 行为一致化）
3. `PmCenter.tsx`：确认无自建导航残留（✅ 已重构）
验收：Rail 点「项目管理」→ 侧栏出现项目面板（可浏览/快改）+ 主区出现看板；两侧数据一致。
预估：~350 行改动。

### M2 看板与表格体验（回应「UI 丑」问题）—— 目标：交互质感对齐 PingCode
1. 看板**拖拽**：HTML5 DnD——卡片跨列=状态流转（确认弹层可关）、列内=sortOrder 重排；

4. 工具条搜索框（标题/描述 contains）
5. 空态/加载态/错误态统一组件
