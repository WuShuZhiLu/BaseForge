# BaseForge 协作纪律与架构约定

## 提交纪律（最高优先级）

- **改完代码禁止自动 commit。** 流程必须是：
  1. agent 改完并确认能启动（tsc + dev 启动验证）
  2. 用户测试并确认功能没问题
  3. 用户明确同意后才 commit
- 禁止把可能的半成品提交上去；一次验收通过一个 commit，不反复追加。
- commit 信息：中文、言简意赅（谁+做了什么+为什么），遵循 Conventional Commits。

## 桌面端三分区模型

桌面端布局固定为三个分区，所有命名、实现、新功能都必须按此归类：

1. **导航栏（Rail）**：最左图标列。放功能入口徽章、插件徽章、账户菜单。
2. **侧边栏（Sidebar）**：导航栏右侧。是各功能模块自己的导航/辅助区——
   知识库放知识树、打开的文档；PM 放项目列表；插件可按自己的需求使用或贡献内容。
3. **工作区（Workspace）**：主区域。知识库放文档编辑、PM 放项目看板等。

命名后缀对应分区：`*Desktop` / `*Mobile`（按平台）、`*Workspace`（③主区全屏视图）、
`*Panel`（②侧栏内嵌面板）、`MiniPanels`（②侧栏迷你面板）。

## 模块化愿景

- 每个功能都是**模块**，外来插件也是**模块**，地位平等。
- 模块按 导航 / 侧边 / 工作 三分区进行规范接入。
- 插件可以根据自身需求，实现自己的三个分区，或修改、嵌入、补充别的模块。
- 未来演进方向（批次C/D）：侧边栏与工作区内容"块化"——注册制、可拖拽、可折叠、状态持久化。

## Rail 徽章规则

- 分割线固定：上组=核心徽章（知识库/收藏/回收站/文件管理/分享管理），
  下组=插件徽章（「插件」徽章固定首位不可动 + 各插件徽章）。
- 组内可拖拽排序（coreOrder/pluginOrder 持久化），禁止跨组；右键可隐藏/管理。
- 拖拽落点用知识树式上/下半内阴影预示，拖拽预演不重排 DOM。
