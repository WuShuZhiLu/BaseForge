# 知识库交互设计：单树 + 库详情页

> 决策者：用户。日期：2026-10-28。状态：设计已定，待实施。
> 前置事实：`aec4416ac`（知识库独立进入两级态）之前的侧栏就是单树；
> 两级态引入了重复根行、折叠头残留、空库弹回、选中丢失等一系列结构性问题，
> 现决定**恢复单树**，并用「库详情页」补上原单树缺少的"知识库作为独立项目"的心智。

## 0. 历史对照（`aec4416ac^` 实测源码，非回忆）

旧单树的真实结构：

- 一棵树，根层**混排知识库与普通文件夹**，同为「图标 + 名称 + 计数」行，只靠图标区分
- 单击 = 选中：文件夹 → 主区列表按该文件夹过滤；文档 → 打开编辑器
- **双击根层文件夹（知识库）= 进入"专注"**（`setFocusRootId`）：顶部出现「← 库名」小条，
  树只剩该库子树；再双击/返回退出
- ＋：有选中节点 → 其下新建；否则根级
- 右键：文件夹与文档共用一个菜单（新建/重命名/删除），知识库没有库级操作
- 专注态只存 `localStorage`，URL 不表达，刷新即丢

当时暴露的问题（`aec4416ac` commit message 原话）：

1. 「知识库 = 独立项目」的心智立不起来（根层和文件夹混排）
2. 进入/搜索/新建的交互未成体系，**专注只有隐形的双击入口**
3. 进入态不落 URL，刷新/分享即丢（URL 化的起点）

本设计的两条不可退让约束：**库不能与文件夹混排成同一行**、**"打开知识库"必须有
可见入口且 URL 可表达**。做法是保留单树结构（不加模式切换），把"库"的身份从
渲染层移到**主区详情页**与**URL**上。

## 1. 设计原则

1. **侧栏一棵树**：根 = 知识库，子 = 文件夹 / 文档；无模式切换，无整块内容替换。
2. **详情页在主区**：点击侧栏的知识库行 → 工作区（主区）显示该库的详情页，
   侧栏结构不变（不聚焦、不隐藏其它库）。
3. **首页不计入文档数**：库详情页是虚拟页面，不是知识树节点、不是 notes 记录；
   文档数/字数统计只算该库子树内的文档节点（文件夹、导图/表格按各自类型计入文档，
   详情页本身永不计入）。
4. **动作语义唯一**：单击 = 选中（并打开对应内容），双击/箭头 = 展开折叠，
   右键 = 节点菜单，＋ = 在当前上下文新建。
5. **URL 即状态**：库详情页 = `/kb/:space/:kbId`；文档 = `/kb/:space/:kbId/notes/:noteId`；
   空间级 = `/kb/:space`。刷新/前进后退/分享天然可恢复。

## 2. 交互模型

### 2.1 侧栏（单树）

```
个人空间 ▾
[搜索]  [筛选]
知识库                     ＋  ⋯  [54]
  ▾ 📘 实际应用      10      ← 知识库根节点（可折叠）
      📁 编译产物     4
      ▾ 📁 部署       6
          📄 上线检查清单
  ▸ 📘 工作笔记       7
  ▸ 📘 设计           8
标签 ...
打开的 ...
```

| 操作 | 行为 |
|---|---|
| 单击知识库根行 | 选中 + 工作区打开该库**详情页**（`/kb/:space/:kbId`） |
| 单击文件夹行 | 选中 + 展开/折叠（不改变主区） |
| 单击文档行 | 选中 + 在编辑器打开文档（现有行为） |
| 双击知识库根行 | 展开/折叠该库子树 |
| 行尾箭头（chevron） | 展开/折叠 |
| 右键任意行 | 新建文档 / 新建文件夹 / 重命名 / 删除 / 置顶（文档） |
| 区块头 ＋ | 有选中节点 → 在其下新建；无选中 → 新建知识库 |
| 拖拽 | 现有行为保留（拖入文件夹、排序） |
| 空库 | 树里照常显示该库根行（计数 0），点击进详情页后由详情页提供新建入口 |

### 2.2 主区

| URL | 主区 |
|---|---|
| `/kb/:space` | 文档列表（现状，medium 列表 + 编辑器） |
| `/kb/:space/:kbId` | **库详情页**（无打开文档时） |
| `/kb/:space/:kbId/notes/:noteId` | 文档编辑器 + 面包屑（库 › 文件夹 › 文档） |

> 打开文档时详情页让位给编辑器；关掉文档回到详情页（若当前库仍是最后一个选中的库）。

### 2.3 库详情页规格

```
[📘]  实际应用 🔒                     ☆ 收藏   分享   ⋯
      10 文档 · 1099 字 · 更新于 10-27 18:22
      👤 @wushuzhilu 等 3 人参与编写

📌 库简介（notebooks.description，可编辑）

目录（点击直达 · 右侧为最近更新时间）
📁 编译产物 ............................ 10-27 18:22
▾ 📁 部署 .............................. 10-26 09:10
     📄 上线检查清单 .................... 10-27 18:22
     📄 环境变量说明 .................... 10-24 15:40
```

- 头部操作：收藏（库级置顶/收藏标记）、分享（分享整个库，沿用现有分享能力）、⋯（重命名 / 删除 / 新建文档）
- 统计口径见 §4；空库时统计显示 `0 文档`，目录区替换为：
  `这个知识库还没有内容 —— [＋ 新建第一篇文档]`
- 目录时间戳 = 子树内该节点及子孙的最大 `updatedAt`

## 3. 状态模型与改动范围

### 3.1 移除的概念

- **进入态 / 聚焦态**（`focusRootId` 作为"切换渲染模式"的开关）——删除列表态/进入态双分支，
  `buildRows` 恒走 `walk(null, 0, [])`（单树）。
- 进入态专属 UI：返回横幅、「知识库 ⌄」隐藏逻辑、列表态库行（单击进入 / 双击进入）、
  「库内/全空间」搜索胶囊随进入态出现的行为 → 一并移除。
- `focusRootId` 保留为**视图辅助**（如"定位到底部标签文档"时展开按需），但不再影响渲染分支。

### 3.2 新增的概念

- `detailKbId`（由 route 派生：`route.kind === "kb" ? route.kbId : null`）：
  决定主区是否渲染库详情页；侧栏只做选中高亮，不改变树。
- `KbDetailPage` 组件（新文件 `frontend/src/components/kb/KbDetailPage.tsx`）：
  接收 `kbNodeId`（树节点 id，由 notebook resourceId 反查得到）+ `spaceId`。
- 统计接口 `GET /api/knowledge-tree/:kbNodeId/stats`（见 §4）。

### 3.3 文件级改动清单

| 文件 | 改动 |
|---|---|
| `components/SidebarDesktop.tsx` | 删除两级态分支（列表态 block、进入态横幅、hide-header 条件）；单树恒渲染；单击库根行 → `pushAppPathState(/kb/:space/:resourceId)`；保留选中/右键/拖拽/搜索分类 |
| `components/kb/KbDetailPage.tsx`（新） | 详情页：头部/统计/贡献者/简介/目录/空态 |
| `App.tsx` | 主区渲染分支：`route.kind === "kb"` → `KbDetailPage`；`note` → 编辑器；其它 → 列表 |
| `components/AppRouteSync.tsx` | `/kb/:space/:kbId` 不再影响侧栏（去掉 enteredKbId 对 URL 的"库层级保护"回归测试点）；写入路径统一 `/kb/:space[/:kbId[/notes/:n]]` |
| `lib/appRoute.ts` | 保持现有形态，`kb` 路由语义改为"打开库详情页"；注释更新 |

## 4. 统计口径（首页不算文档数）

`GET /knowledge-tree/:kbNodeId/stats` 返回：

```json
{
  "docCount": 10,
  "charCount": 1099,
  "updatedAt": "2026-10-27T10:22:00.000Z",
  "contributors": [{ "userId": "…", "username": "wushuzhilu", "displayName": "…" }]
}
```

- **docCount**：该库子树内 `isDeleted = 0` 且 `nodeType != 'folder'` 的节点数。
  详情页不是节点、不计入；文件夹不计入。
- **charCount**：上述文档对应 notes 的 `contentText` 去掉空白后的字符数之和；
  表格/导图节点若无 contentText，按 0 计（不估算）。
- **updatedAt**：子树内节点 `updatedAt` 最大值（空库返回库节点自身的 updatedAt）。
- **contributors**：子树内文档的 `userId` 去重（按文档数降序），最多 3 个，
  附带 users 表的 username / displayName；前端展示「@A 等 N 人参与编写」+ 头像。
- 权限：沿用知识树读权限（无权限返回 404，不泄露存在性）。

## 5. 缺陷对照（本设计如何消掉现有问题）

| 现有缺陷 | 根因（结构） | 本设计的处理 |
|---|---|---|
| 进入空库自动弹回上一级、无法添加 | 反查表仅从有文档的根推导 | 无进入态；空库照常显示在树里，详情页给新建入口 |
| 选中功能丢失，只能进入再删库 | 列表态库行单击=进入 | 单树单击=选中，右键/＋ 完整操作 |
| 进入态仍显示「知识库 ⌄」折叠头 | 两级态共用同一区块头 | 无进入态，不存在该渲染 |
| 「← 库」与「⌄ 库」两行同库重复 | 进入态横幅 + 根行同时渲染 | 无横幅；树里只有一行 |
| 单击语义随层变化 | 两套行渲染 | 单树一套语义 |
